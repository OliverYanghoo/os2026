### 审查结论

在当前 RV64、单段设备树内存、固定 DRAM_BASE/物理映射偏移及 PHYSICAL_MEMORY_END 框架约定下，未发现 page_init 本身需要立即修复的地址越界、计数或保留页问题。

1. 地址偏移在首次 PADDR 使用前设置；npage、pages 在 pa2page 使用前完成初始化。dtb_init 使用的是常量偏移，因此不依赖此前设置全局 va_pa_offset。
2. managed_end 向下对齐且高于 DRAM_BASE，保证 npage - nbase 不下溢；pages 下标区间为 [0, npage - nbase)。
3. 内核后向上对齐放置描述符，描述符末尾再向上对齐得到空闲区起点，保护两处不完整页面。
4. 内存范围加法先检查溢出；描述符乘法先通过剩余容量除以 sizeof(Page) 检查；范围检查的短路顺序防止减法下溢。当前物理上界也保证后续对齐和虚实地址换算不会绕回。
5. 描述符先全部初始化为保留，仅将数组之后的完整页面交给当前管理器。
6. 零空闲完整页时不调用 init_memmap，满足 page_init Spec。但其调用者 pmm_init 仍会无条件执行管理器分配自测，不能据此声称极小内存下完整启动也会成功。

### 默认内存与测试假设

默认物理区间 [0x80000000, 0x88000000)，nbase=0x80000，npage=0x88000，描述符数量 32768。当前 RISC-V 目标对象的 DWARF 信息确认 sizeof(struct Page)=40，数组占用 0x140000 字节，最终空闲页数还要扣除固件、内核和描述符占用。

逐项核对 tools/test_lab2.c 中 Test 1 的八组条件：偏移、设备树非零值、npage、数组非空/对齐/位置、空闲页数、内核尾页保留、描述符首个占用页保留、单个页面的地址往返转换。Test 2 只检查选择的管理器是否为 Best-Fit。

测试盲区包括范围溢出、上界截断、全部描述符初始化状态、精确空闲区边界、所有保留页、数组全部占用页和尾部、零空闲页及真实 DTB 解析。Test 1 用 PPN(设备树报告末尾) 而非裁剪后的末尾作为 npage 预期，因此超过 128 MiB 框架上界时会与正确截断实现产生差异；其空闲页数检查还要求非零。未更改任何评分条件。

## 07：设备树获取物理内存范围与其他平台方法

- 对应任务：物理内存范围获取方法思考题。

### 实际提问

```text

给出我能够理解并用于回答助教提问的说明，不修改代码。
```

### 本实验的读取流程

QEMU virt 在未指定自定义 DTB 时根据虚拟硬件配置生成 DTB；启动固件参与传递或调整，向内核传入 a0=hartid、a1=DTB 物理地址。设备树方法不是逐个物理地址试读写，也不能把平台描述的生成笼统理解为 OpenSBI 必须扫描每个地址。

entry.S 保存参数到 boot_hartid/boot_dtb；kern_init 清理 BSS 后调用 dtb_init；dtb_init 使用 PHYSICAL_MEMORY_OFFSET 将 DTB 物理地址换成当前内核可访问的虚拟地址，检查非零地址及魔数。此转换依赖已有映射，不会自动建立映射，也不负责发现 RAM。

extract_memory_info 使用头部偏移定位结构块和字符串块，依次解释 FDT_BEGIN_NODE、FDT_PROP、FDT_END_NODE、FDT_NOP 和 FDT_END。进入名称以 memory 开头的节点后，找到 reg 属性，读取第一组 64 位基址和 64 位长度，经大端转换后保存到 memory_base/memory_size。get_memory_base/get_memory_size 只是返回缓存结果，不再探测硬件。

当前解析方式隐含父节点 #address-cells=2、#size-cells=2，即地址和长度分别由两个 32 位 cell 表示。示意 reg=<0x0 0x80000000 0x0 0x08000000> 表示 [0x80000000,0x88000000)，长度 128 MiB；最后一个有效字节地址为 0x87ffffff。通用设备树并不保证采用这种 cell 数量，也可以有多组 reg、多段 RAM。

随后 pmm_init/page_init 读取这两个 getter，检查无效范围和加法溢出，裁剪框架上界并处理页对齐；在内核 end 后安排 Page 数组，先把所有描述符置为保留，仅把数组之后的完整空闲页交给 init_memmap。

### 内存存在与可以分配的区别

一般应计算：可分配区 = 受支持的 RAM 区间，扣除所有仍有效的保留区及占用区后，将每个剩余区间向内按页对齐。区间需检查溢出并统一重叠关系，不能把多段 RAM 的空洞一起释放。

需要排除常驻固件、内核镜像、启动栈/页表、Page 数组、仍被使用的 DTB/initrd/启动参数、设备专用 RAM 缓冲区等。MMIO、ROM、未映射空洞和坏内存不能作为普通 RAM；启动占用区只有在完成生命周期交接、没有后续引用时才能回收，常驻固件不能仅因已进入内核就释放。

设备树需结合内存保留块和 /reserved-memory，而不能只看 /memory。no-map 区域还有禁止普通直接映射的要求。当前 dtb.c 虽定义 off_mem_rsvmap，却没有遍历保留表，也没有处理 /reserved-memory；仅取第一个符合条件的 reg 的第一对地址/长度，没有按 cell 数通用解析，也缺少完整的 DTB 长度、偏移及字符串边界校验。

当前 page_init 按固定布局保留固件、内核及描述符所在的前部区域，适用于本实验的布局假设；不能因此声称已处理任意位置的固件/设备保留洞。若后续仍需访问 DTB 或其他启动数据，应保持对应页面被保留，完成复制或解析且无后续引用后才可回收。本轮只解释这些边界，不修改代码。

### 平台比较与盲目探测的问题

- BIOS x86：启动加载器在实模式调用 INT 15h/E820，得到带类型的系统物理地址图，再传给内核；不适用于本实验的 RISC-V，也不能把它当成任意执行模式下都可调用的接口。
- UEFI：加载器在 ExitBootServices 前通过 GetMemoryMap 取得带类型的描述符，并完成内存图交接。退出启动服务后不能再调用该启动服务；常规内存、可回收的启动服务内存、必须保留的运行时内存、NVS 和 MMIO 按类型及生命周期分别处理。UEFI 不仅用于 x86。
- Multiboot2：支持该协议的加载器向兼容内核传递 memory-map 等标签，条目包含起点、长度和类型；内核仍需排除自身、模块及仍在使用的启动信息。这是加载器交接协议，不是独立的硬件探测指令。
- 固定开发板/SoC：可依据板级内存图、已初始化的内存控制器配置和启动阶段记录获得 RAM bank 起点与长度，再由加载器传给内核。需要明确的芯片/板级知识和权限，不能直接跨平台套用；单知道总容量也不能推导全部可分配地址区间。

盲目读写可能碰到 MMIO：读操作也可能弹出设备队列或清除状态，写操作可能改变设备控制状态；在 RAM 内写入测试图案可能覆盖内核、页表或固件。未实现地址、权限/PMP 限制、总线响应问题可能触发访问异常，开启分页后还可能因映射问题产生页缺页。这些结果都不能简单解释为“该地址没有 RAM”；可读写成功同样不能证明其为空闲 RAM。

### 可用于答辩的表述

“本实验的启动阶段通过 a1 交给内核 DTB 的物理地址。entry.S 保存地址，dtb_init 根据页表映射读取并解析 memory 节点的 reg，得到物理内存起点和长度；page_init 再建立描述符、保留已占用页面并注册剩余完整页。其他平台可以通过 BIOS E820、UEFI 内存图或加载器协议传入类似信息，但都需要区分 RAM、保留区和设备地址，不能把报告的整个范围直接释放。盲目试读写既不能可靠判定空闲内存，还可能操作设备或破坏正在使用的数据。”
