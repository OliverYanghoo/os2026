## 选块循环的结论

当前 `best_fit_alloc_pages()` 符合 Best-Fit。扫描到任意位置时，`best` 始终指向已经访问过的、长度不小于请求值 n 的最小空闲块；没有符合条件的块时为 NULL。遇到符合条件但更大的块不更新，遇到更小的块才更新，循环中没有提前返回或 break。扫描结束后才执行摘链和分割，因此不会停在第一个可用块。

空闲链表按地址递增，比较条件使用 `<` 而非 `<=`，同大小时保留先遇到的低地址块。`n > nr_free` 时直接失败；总空闲页数足够但没有连续候选时，遍历结束返回 NULL。这两种失败都不修改链表、块头或计数。

例如，空闲块按地址从低到高依次为 P0 起的 8 页、P12 起的 5 页、P24 起的 3 页、P40 起的 3 页。申请 2 页时，候选依次从 P0 更新为 P12、P24，到 P40 时不更新，最终返回 P24，留下 P26 起的 1 页。First-Fit 则会返回 P0。

## 题目测试如何区分算法

`basic_check()` 主要检查单页分配、释放、计数和状态恢复，不能单独证明选择策略。

`best_fit_check()` 先申请 5 页，再隔离空闲链表，仅释放 P1/P2 和 P4，从而建立低地址的 2 页块与高地址的 1 页块。接着申请 1 页：

```text
低地址                         高地址
P0(已分配) | P1 P2(空闲) | P3(已分配) | P4(空闲)

Best-Fit: 申请 1 页 -> P4；再申请 2 页 -> P1，成功。
First-Fit: 申请 1 页 -> P1；余 P2 与 P4 各 1 页，再申请 2 页失败。
```

因此，后续 `alloc_pages(2) != NULL` 和 `p0 + 4 == p1` 都对策略有约束。不能把未执行这些断言的其他测试当成同等证明。

特别是 `tools/test_lab2.c` 中的 `test_best_fit()` 只检查 `pmm_manager == &best_fit_pmm_manager`，只能证明接入了指定管理器，不能证明管理器内部实现了 Best-Fit。

## 进一步改进的取舍

当前算法分配时扫描 k 个空闲块，时间 O(k)。First-Fit 在找到首个可用块时即可停下，通常扫描更少，但最坏也为 O(k)。本实现释放 n 页时要清理 n 个描述符，再查找插入位置，时间 O(n+k)；相邻合并本身只处理两个邻居，为 O(1)。

### 1. 精确匹配后提前停止

找到 property=n 的块后，剩余空间已经是最小的零，不可能出现更优大小。由于链表按地址递增，第一个精确匹配也满足低地址优先，因此可以停止扫描，改善存在精确匹配时的平均查找时间，最坏仍是 O(k)。本次实现要求扫描所有候选，因此这里只作为后续方案，不更改当前代码。

### 2. 使用按大小索引与按地址索引

用以 `(块大小, 起始地址)` 为键的平衡树进行下界查询，可在 O(log k) 时间找到最小足够大块，并明确同大小规则。但释放时还要查找物理邻居，因此需要另一套地址索引，或有可靠边界元数据的设计。一次分割/合并需要从相关索引删除旧块、更新长度后重新插入，维护操作一般为 O(log k)，同时增加节点字段、实现复杂度和一致性维护成本；释放 n 页的描述符清理仍为 O(n)。

本实验自测会单独保存、清空和恢复 free_list/nr_free。额外索引若没有同步恢复机制，就会与测试隔离状态冲突，甚至引用已不在当前链表中的块，所以不能直接增加隐藏索引并假定现有自测仍兼容。

### 3. 分桶与非空桶位图

按精确页数设置桶，再用非空桶位图查找不小于 n 的最小非空桶，可减少逐块扫描。桶数取决于可管理最大块长度，位图查找成本取决于其长度和分层方式；还需维护按地址的邻接关系以便合并。同一桶若要求低地址优先，任意尾插并不能保证规则，必须有序维护或另建索引，仍有维护成本。

若只使用 2 的幂等粗粒度分桶，桶内块大小可能不同，随便取一块只得到近似适配。要保持严格 Best-Fit，还需要比较桶内候选；若直接向上按桶大小分配，会引入内部碎片。Buddy 的按阶分配也不能直接视为等价的 Best-Fit 优化。

### 4. 小剩余块与碎片处理

Best-Fit 优先减少本次分配的剩余长度，有时能保留较大的连续块供后续大请求使用；但反复切割也可能留下很多小块，增加空闲块数量和后续扫描成本。它不能保证对所有请求序列都比 First-Fit 的外部碎片更少。

本实验按页分配，剩余 1 页仍可用于单页请求，不能一概视为不可用。立即合并可以消除物理相邻的空闲小块，但被已分配页隔开的块无法通过链表操作合并。

“剩余低于阈值就整块分配”会把部分外部碎片转为内部碎片，并影响当前接口：调用者申请 n 页后通常也按 n 页释放；如果实际多占了页面却没有记录真实分配长度，额外页面会无法正确回收。若改为主动跳过产生小剩余块的候选，也会改变严格 Best-Fit 的选择规则。因此本实验保留所有完整剩余页，不直接采用此类阈值策略。

比较改进方案时，应对同一请求序列统计：平均/最大扫描长度、分配释放耗时、额外元数据量、小块数量分布、最大连续空闲块，以及总页数足够时的连续分配失败次数。单次分配的剩余长度不足以代表长期碎片表现。

## 报告应说明的核心函数与状态

| 函数或模块 | 应解释的行为及状态变化 |
|---|---|
| best_fit_init | 建立空哨兵链表；nr_free=0 表示尚无注册空闲页 |
| best_fit_init_memmap | 对 n 页解除保留、清理引用计数及旧状态；建立块头；nr_free+=n；有序插入并合并 |
| best_fit_alloc_pages | 两种失败情形均保持状态；全表选最小块，同大小低地址优先；整块摘链或在 best+n 建剩余头；nr_free-=n |
| best_fit_free_pages | 检查页面状态，清理 n 页状态/引用，建立释放块头；nr_free+=n；调用插入合并 |
| best_fit_insert | 插入一次；只在物理连续时合并；先前块后后块，前向合并后 base=p；被吸收块头清标志、property 和链表节点；合并不增加 nr_free |
| best_fit_nr_free_pages | 返回页总数，不是空闲块数；与所有块头 property 之和一致 |
| best_fit_pmm_manager / init_pmm_manager | 函数指针绑定、选择管理器及输出名称；将算法与 page_init 解耦 |
| basic_check / best_fit_check | 基本正确性和策略区别；保存/恢复链表及计数；结束后恢复原有空闲状态 |

分割示例：P24 的 3 页块申请 2 页后，P24 的块头标志清零、property=0；P26 设置块头标志、property=1；nr_free 减少 2。

双向合并示例：空闲 [0,2)、[4,6)、[10,12) 共 6 页，释放 [2,4) 后得到 [0,6)、[10,12)，nr_free=8；再释放 [6,10) 后得到 [0,12)，nr_free=12。最终仅 P0 为块头，property=12；增加的页数分别只是 2、4，不能把已空闲的左右邻块重复加进计数。

还应说明 PageProperty=0 不能单独证明页面已分配，因为空闲块内部页面也没有该标志。块头由链表和标志共同描述；property 只在空闲块头处表示有效长度。
