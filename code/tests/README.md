# 物理内存管理隔离检查

## Best-Fit 检查

在 `code/` 目录运行：

```bash
conda activate os2026
make
python3 tools/check_best_fit.py
```

`best_fit_check.c` 包含实际的 `best_fit_pmm.c`，以便同时检查静态链表的不变量；单独编译实际 `pmm.c`，调用 `pmm_init()` 验证管理器选择、页初始化和 `.check` 绑定。没有复制分配算法，也没有改变 `basic_check()`、`best_fit_check()` 或 `tools/test_lab2.c` 的内容。

脚本在 QEMU RISC-V 中分别运行 `-O0`、`-O2` 两种构建，每种构建检查：

- 现有 `basic_check()`、`best_fit_check()`，以及题目提供的两个接口测试。
- 空链表、乱序注册、初始化状态清理、相邻注册区域合并。
- 选择最小足够大块；同大小时选择低地址；分割和整块分配。
- 总空闲页数足够但没有足够大的连续块时，分配失败且状态不变。
- 头部、中间、尾部释放插入；仅前块、仅后块及前后同时合并。
- 512 次固定种子的分配/释放，与独立的逐页位图模型核对返回地址、页状态、块长度、链表顺序、双向链接和空闲页计数；最终回收全部页面。

成功时输出 `BEST_FIT_PASS`。日志位于 `obj/check-best-fit/`，会被 `make clean` 删除。

检查使用独立的 `page_init_boot.S` 和 UART 输出，并以测试 getter 提供默认内存信息。因此通过表示生产管理器及其初始化调用链在隔离环境中通过检查，不表示正式入口汇编、SBI、真实 DTB 解析或完整内核启动通过。

2026-10-15 的正式镜像启动检查在进入管理器之前触发取指页缺页：入口启用 Sv39 时，当前低地址没有对应的恒等映射。本轮保持正式入口不变。持久化结果见 [Best-Fit 验证记录](../../report/evidence/2026-10-15-best-fit/README.md)。

## page_init 检查

在 `code/` 目录运行：

```bash
conda activate os2026
make obj/kern/mm/pmm.o
python3 tools/check_page_init.py
```

本检查无需先实现 Best-Fit。它在 QEMU RISC-V 中执行真正的 `pmm.c` 内的静态 `page_init()`，通过测试翻译单元包含该文件，不复制或替换初始化算法，也不改变正式内核的函数可见性。

## 验证内容

共 13 个用例：默认 128 MiB、较小的 8 MiB、256 MiB 报告值被内存上界截断、未对齐的内存末尾、零长度、零基址、64 位范围溢出、范围位于 DRAM 以下、内存范围排除内核、范围不足以容纳内核、描述符空间不足、描述符可容纳但没有完整空闲页、设备树基址略高于 DRAM_BASE。

同时验证：

- 页描述符地址对齐，数量正确，数组尾部哨兵字节未被越界覆盖。
- 调用分配器前，所有描述符已经初始化并标记为保留，引用计数与 property 为零。
- 只注册一次正确的连续空闲区域；无空闲页时不调用注册函数。
- 固件、内核与描述符占用的页保持保留，描述符与页号转换可往返。
- 无效输入在写入描述符、调用管理器之前触发预期 panic。

默认、小容量、未对齐上界及调整起点的场景还调用未修改的 `tools/test_lab2.c` 中的 `test_page_init()`。该测试假设设备树内存不超过框架上界且有空闲页，所以超上界和零空闲页场景使用独立断言，不修改题目测试以适配这些情况。

## 测试边界

`get_memory_base()`、`get_memory_size()` 由用例提供返回值，管理器使用检查回调，分别隔离设备树解析和分配算法。本检查不验证实际 DTB 解析、First-Fit/Best-Fit 算法、SBI 输出或完整内核启动。

`page_init_boot.S` 是独立测试入口，额外提供测试用的低地址映射以完成分页切换和 UART 输出；正式 `kern/init/entry.S` 不被修改。测试内核输出使用 UART，避免未完成或无关模块影响初始化检查。

编译及运行日志位于 `obj/check-page-init/`，`make clean` 会删除该目录。每个预期 panic 用例独立启动 QEMU，避免中断其他用例。临时内核在结束后删除，只保留文本日志。
